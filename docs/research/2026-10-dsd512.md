# DSD512 on the T1

- **Status:** Proposal for the maintainers. Not a decision.
- **Date:** 2026-10-22
- **Requirements:** OS-020 (bit-perfect playback including DSD, native and DoP); [ADR 0006](../adr/0006-native-dsd-through-upstream-driver-work.md) (native DSD through upstream driver work).
- **Sources:** [CS43198 spec sheet](https://github.com/opendap-project/parts-lib/blob/main/Cirrus-Logic/CS43198-CNZR.md) (DS1156F2), the mainline `cs43130` driver, board ADR 0001 (Cirrus DAC family) and ADR 0010 (master clocks).

## 1. The constraint

DSD512 is a 1-bit stream at 512 × 44.1 kHz = 22.5792 MHz per channel.

| Path into the CS43198 | Limit | Source |
|---|---|---|
| Native DSD input (DSDCLK, DSDA, DSDB) | DSD64, DSD128, DSD256. DSDCLK at most fMCLK_INT / 2 = 11.2896 MHz | DS1156F2 Table 3-19 |
| DoP over the PCM port (ASP) | PCM at most 384 kHz, so DoP reaches DSD128 (352.8 kHz); DSD256 over DoP would need 705.6 kHz | DS1156F2 p. 2, Table 3-18 |
| Mainline driver today | DoP at 176.4 and 352.8 kHz only (DSD64, DSD128); no native DSD | `cs43130` driver |

**The on-board DAC cannot play DSD512 natively, in any mode.** This is the chip, not the driver. Every DAC in the Cirrus family the board uses (ADR 0001) shares the DSD256 ceiling, as far as the datasheets read so far show (**UNVERIFIED** for every family member other than the CS43198).

## 2. Proposal: three tiers, each stated honestly

| Tier | Formats | How | Bit-perfect |
|---|---|---|---|
| **A. Native, on-board** | DSD64, DSD128, **DSD256** | Native DSD through the CS43198's dedicated DSD pins, fed by the SoC's I2S-TDM block (ADR 0006 work, extended from DSD128 to DSD256). The board already routes DSD on its own nets (board pin plan, cross-validation F28), and DSDCLK 11.2896 MHz comes from the 22.5792 MHz MCLK (ADR 0010) | Yes |
| **B. Converted, on-board** | **DSD512** (and DSD1024 files, if they appear) | The playback engine converts DSD512 in software to PCM 352.8 kHz / 32-bit (default), or to DSD256 (option, if a sigma-delta modulator of adequate quality is available as open source; **UNVERIFIED**), and plays that natively | No, and labelled so in the UI ("DSD512 → PCM 352.8 kHz") |
| **C. Native, external** | **DSD512** and above | The T1 as USB host on the main USB-C streams native DSD to a USB DAC that supports it (ALSA `snd-usb-audio` native DSD formats, per-device quirks), DoP as fallback | Yes |

### Why this split

- It keeps the promise exact: the T1 never claims native DSD512 on its own outputs, because the hardware cannot do it, and it never hides a conversion (OS-020 and the voice rule "engineering before promises").
- Tier A covers the DSD rates the on-board DAC supports, at their full native quality.
- Tier B lets every DSD512 file play on the headphone outputs. Converting DSD to high-rate PCM is the established path for DACs without DSD512 support. The RK3566's four Cortex-A55 cores with NEON have capacity for one stereo DSD512 decimation stream; the battery cost is to be measured (**UNVERIFIED**).
- Tier C gives native DSD512 to users who own a DAC that supports it, with no compromise.

### What it does not do

Native DSD512 on the on-board outputs would require a different DAC family. That reopens board ADR 0001 (Cirrus, confirmed by the maintainers), the clocking (ADR 0010), the analog stage and the power budget, for one format. This proposal does not recommend it for the T1.

## 3. Work items

1. **Driver, DAC side:** native DSD in the `cs43130` driver through the XSP/DSD pins, DSD64–DSD256, with the right DSDCLK divider per rate; upstream (ADR 0006).
2. **Driver, SoC side:** DSD formats in the Rockchip I2S-TDM driver, streaming raw bits at up to 11.2896 MHz per data line without framing gaps; upstream (ADR 0006). Whether the block can do this cleanly is **UNVERIFIED** (pin plan risk 3).
3. **Playback engine:** DSD512 → PCM 352.8 kHz / 32-bit conversion as a selectable, visible mode; the conversion filter is documented and its output verified against a reference implementation with captured samples (TK-012).
4. **USB host DSD:** native DSD to USB DACs through ALSA, with DoP fallback; a compatibility list built from tests.
5. **Verification:** bit-exact capture of tiers A and C (on-board through the RP2354A I2S/DSD tap, BRD-040/041; USB with a capture-capable DAC or the virtual T1); tier B checked for correctness of the conversion, not for bit-perfection.

## 4. Decision needed

- Accept the three tiers as the DSD512 answer for the T1 (recommended), or reopen the DAC family for native on-board DSD512.
- If accepted: OS-020 is restated as "bit-perfect up to DSD256 on-board and up to the external DAC's limit over USB; higher DSD rates on-board are converted and labelled", and ADR 0006 is extended from DSD128 to DSD256.
